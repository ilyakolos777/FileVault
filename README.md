# FileVault

[![Full Application CI](https://github.com/ilyakolos777/FileVault/actions/workflows/main.yml/badge.svg)](https://github.com/ilyakolos777/FileVault/actions/workflows/main.yml)   [![Server Tests (C#)](https://github.com/ilyakolos777/FileVault/actions/workflows/server-tests.yml/badge.svg)](https://github.com/ilyakolos777/FileVault/actions/workflows/server-tests.yml)  [![Client Tests (Python)](https://github.com/ilyakolos777/FileVault/actions/workflows/client-tests.yml/badge.svg)](https://github.com/ilyakolos777/FileVault/actions/workflows/client-tests.yml)

**FileVault** — это надежное клиент-серверное приложение для удаленного управления файлами, построенное на базе собственного протокола прикладного уровня поверх TCP. Проект обеспечивает безопасное хранение, многопоточную передачу данных, строгий аудит действий и автоматическое версионирование файлов.

## Ключевые возможности

* **Кастомный TCP-протокол:** Двусторонний обмен управляющими командами и бинарными потоками без проблемы "склеивания" пакетов (строгое разделение заголовков и Payload).
* **Умная докачка файлов (Resumable Transfer):** Поддержка возобновления прерванных загрузок (PUT) и скачиваний (GET) с точным байтовым позиционированием.
* **Автоматическое версионирование:** При попытке перезаписи существующего файла сервер автоматически генерирует резервную копию с расширением `.bak`.
* **Многопоточность и Concurrency:** Сервер способен параллельно обслуживать множество изолированных клиентских сессий благодаря асинхронной архитектуре и использованию `ConcurrentDictionary`.
* **Защита данных (Security):** Встроенная защита от атак типа *Path Traversal*, запрет одновременных входов под одним логином и потокобезопасная блокировка файлов при записи (File Locking).
* **Журналирование (Аудит):** Потокобезопасная запись всех действий пользователей (UPLOAD, DOWNLOAD, DELETE, RENAME) в структурированный лог-файл (TSV) с защитой от инъекций спецсимволов.
* **Современный GUI:** Асинхронный графический интерфейс клиента на PyQt6 (паттерн Perfect Dark) с кастомными анимациями (LiquidButton) и "тихим" фоновым поллингом файловой системы.

## Архитектура проекта

Проект логически и физически разделен на два независимых узла:

1. **Сервер (C# / .NET 10):** 
   * Высокопроизводительный бэкенд, обрабатывающий сетевые сокеты через `TcpListener`.
   * Отвечает за маршрутизацию команд (`CommandParser`), работу с жестким диском (`StorageManager`) и ведение журнала (`HistoryLogger`).
2. **Клиент (Python 3.14 / PyQt6):**
   * Толстый клиент с графическим интерфейсом.
   * Тяжелые сетевые операции вынесены в независимые потоки `QThread` (`NetworkWorker`, `TransferWorker`), что гарантирует отзывчивость UI даже при передаче гигабайтных файлов.

##  Установка и запуск

### Требования
* Для сервера: .NET 10 SDK
* Для клиента: Python 3.14+

### Запуск сервера
```bash
  cd server/StorageServer
  dotnet build -c Release
  dotnet run --project StorageServer/StorageServer.csproj
```

### Запуск клиента
```bash
cd client
python -m venv .venv
source .venv/bin/activate  # Для Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

##  Тестирование и CI/CD

Проект обладает **100% покрытием кода модульными тестами**. В репозиторий интегрированы GitHub Actions, автоматически запускающие проверки при каждом пуше.

* **Сервер:** Тестирование реализовано с помощью `xUnit`. Для верификации сетевого слоя применяется продвинутое имитационное моделирование (TCP Loopback), позволяющее тестировать передачу байтов в памяти без открытия реальных портов.
* **Клиент:** Тестирование реализовано через `pytest`, `pytest-qt` и `pytest-mock`. Для CI/CD конвейеров на базе Ubuntu используется виртуальный фреймбуфер `Xvfb` для безголового (headless) тестирования графических компонентов.

**Запуск тестов локально для сервера:**
```bash
# Тесты сервера
cd server/StorageServer && dotnet test
```

**Запуск тестов локально для клиента:**
```bash
cd client && python -m pytest
```

##  Руководство пользователя (Как это работает)

Приложение FileVault спроектировано так, чтобы скрыть сложные сетевые процессы за минималистичным и интуитивно понятным интерфейсом. Ниже описан основной жизненный цикл работы с программой.

### 1. Подключение и Авторизация
При запуске клиента вас встречает стартовый экран. 
* Введите IP-адрес сервера (для локального запуска оставьте `127.0.0.1`) и порт (`5050`).
* Введите ваше имя пользователя (Логин). 
* **Под капотом:** Сервер использует регистронезависимую проверку. Если пользователь `Admin` уже находится в системе, попытка входа под логином `admin` или `ADMIN` с другого устройства будет мгновенно заблокирована сервером (ERR 403) для предотвращения конфликтов.

### 2. Главное рабочее пространство (Workspace)
После успешного входа открывается панель управления файлами. В центре расположена таблица, отображающая:
* Имя файла.
* Точный размер (автоматически форматируется в B, KB, MB, GB).
* Дату последнего изменения.
* Наличие резервной копии (`.bak`).

**Под капотом (Silent Polling):** Вам не нужно постоянно нажимать кнопку "Обновить". Каждые 3 секунды клиент в фоновом режиме незаметно опрашивает сервер. Если другой пользователь загрузит или удалит файл, ваша таблица обновится автоматически. Опрос приостанавливается на время скачивания или загрузки тяжелых файлов, чтобы не забивать канал.

### 3. Операции с файлами (Smart Transfers)

* ** Загрузка файла (Upload):** 
  Нажмите «Загрузить файл» и выберите документ на вашем ПК. 
  *Умная докачка:* Если файл с таким именем уже есть на сервере, клиент сверит их размеры. Если произошел обрыв связи, программа предложит **докачать** недостающие байты, вместо того чтобы передавать гигабайты данных заново. Если вы выберете перезапись, сервер сохранит старую версию файла с расширением `.bak`.
  
* **Скачивание (Download):** 
  Выберите файл в таблице и нажмите «Скачать». Если вы скачиваете файл в папку, где уже есть его недокачанный фрагмент, FileVault автоматически возобновит загрузку с нужного байта (offset).
  
* **Восстановление (Скачать .bak):**
  Если кто-то случайно перезаписал важный отчет, выделите этот файл и нажмите «Скачать .bak», чтобы извлечь его предыдущую рабочую версию.

* **Переименование и Удаление:** 
  При переименовании или удалении сервер эксклюзивно блокирует файл (File Locking), чтобы никто другой не смог скачать его в этот момент. При удалении основного файла его `.bak`-версия также стирается для освобождения места.

### 4. Журнал и Аудит операций
Каждое действие (загрузка, скачивание, удаление, переименование) строго фиксируется сервером.
* Нажмите **«История файла»**, выделив конкретный документ, чтобы увидеть, кто и когда его создал или изменял.
* Нажмите **«Журнал (общий)»**, чтобы получить полную хронологию событий на сервере по всем пользователям.
